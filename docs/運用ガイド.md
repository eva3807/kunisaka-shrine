# 國坂神社 公式サイト 運用ガイド

## この仕組みの狙い

- **平時（お父様）**：コードを一切触らず、ブラウザの管理画面から
  「お知らせ」「授与品（正月）」「御朱印」「行事」などを追加・修正できる。
- **長期休み（あなた）**：デザイン変更・新セクション追加など、コードが必要な作業を担当。
- 文章・写真は `src/_data/*.json` に分離。管理画面が壊れても GitHub 上で直接直せる。

---

## 全体の流れ

```
お父様が管理画面で編集
      │  「保存」
      ▼
GitHub の main ブランチに自動コミット
      │
      ▼
GitHub Actions が Eleventy でサイトを再生成（自動）
      │
      ▼
GitHub Pages に公開（数分で反映）
```

---

## ディレクトリ構成

| 場所 | 中身 | 誰が触るか |
|---|---|---|
| `src/_data/*.json` | 本文・写真の指定（お知らせ／授与品／御朱印／行事 ほか） | 管理画面が自動更新。手編集も可 |
| `src/index.njk` | ページの雛形（HTML/CSS/JS）。デザインはここ | あなた（コード作業） |
| `src/admin/config.yml` | 管理画面の項目定義 | あなた（項目を増やすとき） |
| `eleventy.config.js` | ビルド設定 | あなた |
| `.github/workflows/deploy.yml` | 自動公開の設定 | 基本触らない |
| `_site/` | 生成物（Gitには含めない） | 触らない |

管理できるデータ:

| ファイル | セクション |
|---|---|
| `oshirase.json` | お知らせ |
| `jyoyohin.json` | 授与品 |
| `goshuin.json` | 御朱印 |
| `yotei.json` | 予定・連絡（境内清掃など。カレンダーに載る） |
| `gyoji.json` | 年中行事（毎年の祭典。カレンダーに載る） |
| `keidai.json` | 境内案内 |
| `sakuhin.json` | メディア・作品 |
| `faq.json` | よくある質問 |
| `settings.json` | トップ画像・住所・電話・SNS・地図 |

## 初回セットアップ（あなたが一度だけ行う）

### 1. このブランチをレビューして main へ取り込む

```
git checkout feature/cms-poc
npm install
npm start        # http://localhost:8080 で表示確認
```

問題なければ `main` にマージ。

### 2. GitHub Pages の配信元を切り替える

GitHub リポジトリ → **Settings → Pages** →
**Build and deployment → Source** を **「GitHub Actions」** に変更。

> これで `main` に push されるたびに自動ビルド＆公開されます。
> （今までの「main ブランチの index.html を直接配信」から切り替わります）

### 3. 管理画面を選ぶ（2種類を同梱済み。どちらか片方を使う）

編集対象はどちらも同じ `src/_data/*.json` です。

#### 方法A：Pages CMS（おすすめ・セットアップ不要）

- 設定ファイル：リポジトリ直下の `.pages.yml`（同梱済み）
- お父様の操作：<https://app.pagescms.org> で「Sign in with GitHub」→
  `eva3807/kunisaka-shrine` を選ぶ → 編集 → Save
- 中継サーバー・OAuth登録は不要。すぐ使えます。

#### 方法B：Sveltia CMS（サイト内に管理画面を持つ／中継サーバーが必要）

`src/admin/` に同梱。GitHub ログインに OAuth 中継が必要です（Cloudflare Workers、無料）。

1. <https://github.com/sveltia/sveltia-cms-auth> の手順で Worker をデプロイ
2. GitHub → Settings → Developer settings → **OAuth Apps** で新規登録
   - Authorization callback URL: `https://<あなたのWorker>.workers.dev/callback`
3. Worker の環境変数に Client ID / Secret を設定
4. `src/admin/config.yml` の `base_url` を
   `https://<あなたのWorker>.workers.dev` に書き換えてコミット
5. お父様の操作：`https://eva3807.github.io/kunisaka-shrine/admin/` を開いてログイン

> まず方法Aで運用を始め、余裕があれば方法Bへ移行、という進め方が安全です。
> 使わない方の設定ファイル（`.pages.yml` または `src/admin/`）は残しておいても害はありません。

### 4. お父様を Collaborator に追加

Settings → Collaborators → お父様の GitHub アカウントを追加（Write 権限）。

## お父様向け：更新のしかた

1. 管理画面を開く
   - 方法A（Pages CMS）：<https://app.pagescms.org> → GitHubでログイン → リポジトリを選ぶ
   - 方法B（Sveltia CMS）：`https://eva3807.github.io/kunisaka-shrine/admin/` → GitHubでログイン
2. 左のメニューから編集したい項目（例：「お知らせ」）を選ぶ
4. 「＋ 追加」で新しい項目を作る／既存の項目を選んで直す
   - 写真は「写真」欄にドラッグ＆ドロップでアップロード
   - 「公開する」をオフにすると、消さずに非表示にできる
5. 右上の **「保存」**
6. 数分待つと <https://eva3807.github.io/kunisaka-shrine/> に反映される

### 行事カレンダーの使い分け

| 登録したいもの | 開く項目 |
|---|---|
| 毎年決まっている祭典（例大祭・歳旦祭など） | **年中行事** |
| 今年だけの予定・連絡（境内清掃・会合・臨時祭典など） | **予定・連絡** |

- どちらもトップページの**カレンダー**と**「次の行事・お知らせ」**に自動で表示されます。
- 「年中行事」の**月・日**の欄を空欄にすると、カレンダーには載らず一覧表にだけ載ります
  （「2月」「伝承」など日取りが定まらないもの向け）。
- 同じ行事を両方に登録しても、サイト上は1件にまとめて表示されます
  （時間・場所が入っている「予定・連絡」側が優先されます）。
- 終わった予定は消さずに「公開する」をオフにしておけば、来年の参考になります。

### 困ったとき

- 保存しても変われない → 5〜10分待つ。GitHub の「Actions」タブが緑✓か確認
- 間違えて保存した → GitHub の履歴からいつでも元に戻せる（あなたが対応）

## 設計上のメモ・今後の候補

- **SEO**：本文は生成後の HTML に含まれるので、従来どおり検索エンジンに読まれる
  （クライアント側 JavaScript で描画する方式は避けた）。
- **画像**：既存の imgur 画像はそのまま動く。順次 `src/images/uploads/` へ移すと
  リンク切れリスクが減る。
- **構造化データ**：`JSON-LD`（`Place` / `Event`）を `index.njk` に追加すると
  行事が Google にイベントとして認識されやすい。データは `gyoji.json` を流用可能。
- **お知らせの表示件数**：現在は全件表示。多くなったら `index.njk` の `recent` に
  `| head(5)` 相当の制限を入れる。
- **バックアップ**：内容はすべて Git 履歴に残るため、別途バックアップ不要。
